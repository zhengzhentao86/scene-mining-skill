# 挖掘场景（S3）

把 S2 人群匹配表 + S1 买点库，转成一份"具体到能开机就拍"的场景需求卡 HTML 报告。场景 = 人群 × 买点 × 时刻 的三维交叉，禁止凭空想。

## 输入

S1 买点库 + S2 人群匹配表（HTML 报告路径或链接，也可直接粘贴买点/人群清单）。只消费 Tier 1 买点 × 主攻人群做主攻场景；可测试/待确认进备选池。

## 执行流程（四步）

1. **内容侧先探（先搜后写，禁止凭空想）**——用「品类词 × 场景词」检索抖音至少 3 组关键词（如"面试 穿搭""通勤 双肩包""油污净 测评""手机 分期"）。收集：本品类真实在哪些场景被讨论、有没有现成爆款模板（记录标题+互动量）。候选场景必须来自这些内容信号，常识只能做补充。
2. **交叉组合**——对每个「主攻人群 × 主攻买点」问"这个人会在什么时刻想起这个买点？"，产出候选场景清单（场景名 + 一句话）。
3. **四问填充**——对每个候选逐条回答：触发时刻（时间/地点/事件三要素至少两个）/ 场景画面（人物/环境/动作/冲突，能开机就拍）/ 具体痛点（有画面感，不是"不方便"）/ 拍摄建议（镜头 + 口播钩子）。
4. **成卡排序**——按 Schema 成卡。主攻 = 已验证爆款模板 + Tier1 人群买点；有信号无模板或非 Tier1 = 可测试；内容有信号但缺商品事实 = 待确认（标注需商家确认什么）。每轮至少：主攻 ≥ 4 张（含已验证模板场景）+ 可测试 ≥ 2 张。

完整提示词见 [references/prompts.md](references/prompts.md)，字段口径见 [references/schema.md](references/schema.md)。

## 场景卡版式（硬约束）

每张卡固定：**场景名 + 优先级徽章**，然后四行——触发时刻 / 场景画面 / 具体痛点 / 拍法（镜头 + 口播钩子），外加一行 **✓ 已验证**。核心要求：**具体到能开机就拍**，拒绝"日常生活"这种空场景。

## 内容侧核验要点

- 好场景不是想出来的，是先在抖音里看到、再写成卡的：每条场景必须过核验（✓已验证 或 明确标注"蓝海待测"）。
- 已验证爆款模板优先：面试变装、同学种草、统一条件实测、价格冲突、收纳空间翻倍、柜姐测评、"久吹不头疼" 等都是已跑通的模板类型，命中模板的场景直接升主攻。
- 品类风险会被内容侧暴露（油污净"打假测评"、鞋垫"智商税"质疑）→ 策略随之改变（先实证再承诺、不碰疗效承诺）——这是 skill 给商家的增量价值。
- 同质场景必须合并：2 张以上同质即合并，不注水。
- 证据标注来源类型：本商品事实 vs 抖音同品类内容，不混读。

## 输出与交付

生成场景需求卡 HTML，结构与样式参照 [assets/report-template.html](assets/report-template.html)（骨架）和 [assets/example/](assets/example/)（七个跨品类真实样例）：

- `camel-scene.html` — 服饰鞋包（骆驼女鞋）：变装/同学种草模板
- `kipling-scene.html` — 箱包（双肩包）：通勤/开学选包
- `tuli-scene.html` — 家居清洁（油污净）：三段实测/退租押金
- `bulamai-scene.html` — 出行（行李箱）：收纳空间翻倍
- `mcm-scene.html` — 轻奢（波士顿包）：柜姐尺寸测评
- `gouge-scene.html` — 健康（鞋垫）：久站实测/踩屎感
- `fansheng-scene.html` — 小家电（负离子风扇）：办公室久吹不头疼

> 七个样例覆盖七种不同品类与决策逻辑，验证同一套场景挖掘流程跨品类稳定：每个都挖出"具体到能开机就拍、且带已验证内容证据"的场景。

- **Hero**：商品名 + 输入简注（主攻人群 × 主攻买点）
- **场景卡**：按主攻→可测试排列；每卡含触发/画面/痛点/拍法/✓已验证
- **页脚**：资料来源 + 口径 + "由 scene-mining Skill 生成"

通过 `present_files` 交付 HTML 报告。对外只交付运行样例，不交付 schema 和提示词。
